Konfigurationsreferenz

Klicke in der App auf das (i) neben einem Feld für dieselben Hinweise. Die meisten Felder kannst du bei ihren Standardwerten belassen.

Wohin verbunden wird

  • Verbindungsname — eine in der Seitenleiste angezeigte Bezeichnung, nur für dich. Sie beeinflusst nicht, wie die Verbindung funktioniert.
  • Entfernte Anmeldung (Benutzer@Host) — der SSH-Benutzername und Host (oder dynamische DNS-Name) des entfernten Macs, z. B. alex@myhome.example.com — dasselbe user@host, das du ssh geben würdest.
  • Entfernter SSH-Port — der TCP-Port, über den der SSH-Server des entfernten Macs erreicht wird. Oft nicht 22, weil Router häufig einen eigenen äußeren Port (wie 22022) auf den SSH-Port des Macs im Heimnetzwerk weiterleiten.

Ports

  • Lokal weitergeleiteter Port — ein freier Port auf diesem Mac. Der Home-Sharing-Port der entfernten Mediathek wird hierher getunnelt, sodass eine App, die auf localhost an diesem Port schaut, die entfernte Mediathek erreicht.
  • Entfernter Media Sharing-Port — der Port, auf dem Home Sharing drüben auf dem entfernten Mac lauscht — normalerweise 3689, der Standard-DAAP-/Home-Sharing-Port. Ändere ihn nur bei einem ungewöhnlichen Aufbau.

Verhalten des Tunnels

  • SSH-Control-Socket-Pfad — ein lokaler Dateipfad für den Hintergrund-Control-Socket von ssh, der die App den Tunnel sauber schließen lässt (ssh -O exit), statt den Prozess abzuwürgen.
  • Server Alive Interval — wie oft, in Sekunden, ssh das entfernte Ende anpingt, um den Tunnel durch Router und Firewalls am Leben zu halten und schnell zu merken, wenn er stirbt.
  • Traffic-Abfrageintervall — wie oft, in Sekunden, das Datenverkehr-Panel nettop neu erfasst. Jede Messung dauert einige Sekunden; ein kürzeres Intervall führt sie einfach hintereinander aus.
  • SSH-Kompression — schaltet die Kompression von ssh ein (-C). Sie tauscht ein wenig CPU gegen einen kleineren Datenstrom, was die Wiedergabe über eine langsame oder latenzreiche Heimverbindung spürbar glätten kann. Kann bedenkenlos eingeschaltet bleiben.
