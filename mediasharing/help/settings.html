Configuration reference

Click the (i) beside any field in the app for the same notes. Most fields can be left at their defaults.

Where to connect

  • Connection name — a label shown in the sidebar, for your reference only. It doesn't affect how the connection works.
  • Remote login (user@host) — the SSH username and host (or dynamic-DNS name) of the remote Mac, e.g. alex@myhome.example.com — the same user@host you'd give ssh.
  • Remote SSH port — the TCP port the remote Mac's SSH server is reached on. Often not 22, because routers commonly forward a custom outside port (like 22022) to the Mac's SSH port inside the home network.

Ports

  • Local forwarded port — a free port on this Mac. The remote library's Home Sharing port is tunneled to here, so an app looking at localhost on this port reaches the remote library.
  • Remote Media Sharing port — the port Home Sharing listens on over on the remote Mac — normally 3689, the standard DAAP / Home Sharing port. Change it only for an unusual setup.

Tunnel behaviour

  • SSH control socket path — a local file path for ssh's background control socket, which lets the app close the tunnel cleanly (ssh -O exit) instead of killing the process.
  • Server Alive Interval — how often, in seconds, ssh pings the remote end to keep the tunnel alive through routers and firewalls and to notice quickly if it dies.
  • Traffic poll interval — how often, in seconds, the Traffic panel re-samples nettop. Each sample takes a few seconds; a shorter interval just runs them back to back.
  • SSH compression — turns on ssh's compression (-C). It trades a little CPU for a smaller data stream, which can noticeably smooth playback over a slow or high-latency home connection. Safe to leave on.
